# Лавка Странника — Telegram-магазин нейросетей

Бот на aiogram 3, мини-приложение, админка в чате и полноразмерная админ-панель для браузера на aiohttp + **PostgreSQL**. Категории: ChatGPT, CapCut, Gemini. Реальные товары, цены и остатки добавляет владелец; демо-покупок и выдуманного баланса нет.

## Меню бота

- `/menu` и `/start`: фотография `webapp/1.jpg` и шесть синих кнопок: «🛒 Товары», «🏪 Лавка Странника», « Бонус», «👤 Профиль», «💰 Кошелёк», «🛟 Техподдержка».
- «🎁 Бонус» — реферальная программа: личная ссылка `t.me/…?start=ref_<ID>` с кнопкой копирования, сколько друзей пришло, их оборот и начисленные бонусы (**3 %** от оплаченных покупок приглашённых).
- «👤 Профиль»: `webapp/2.jpg`, число купленных единиц, потраченная сумма, баланс, номер в лавке, любимый товар и кнопка **« Предзаказы»** — личная полка предзаказов. Учитываются только заказы со статусом `paid` или `done`.
- «💰 Кошелёк»: баланс, пополнения на 100, 250, 500, 1000 и 1500 ₽ через администратора и оплата заказа с баланса.
- «🛟 Техподдержка»: ссылка на пользователя из `SUPPORT_USERNAME` (по умолчанию `DitzmBack`), политика конфиденциальности (`PRIVACY_POLICY_URL`) и пользовательское соглашение (`USER_AGREEMENT_URL`).
- Кнопки «Товары» и категорий показывают список прямо в чате; «🏪 Лавка Странника» открывает мини-приложение, если задан `WEBAPP_URL`.

Цвета кнопок в чате: товар <b>зелёный</b>, если есть в наличии, и <b>красный</b>, если закончился; «Купить» — зелёная; «Назад», «Отмена» и удаление — красные; кнопка предзаказа — без цвета (это не покупка, а заявка на поступление). Синий цвет — официальное поле Telegram `style="primary"`; старые клиенты могут показывать кнопки стандартно.

## Оплата и баланс

Покупатель оплачивает заказ **с баланса**: в мини-приложении доступна только кнопка «Оплатить с баланса», и заказ становится `paid`, только если баланса хватает. Если денег не хватает, сервер отвечает `409 Недостаточно средств на балансе.` — это не сбой мини-приложения, а пустой баланс.

Пополнение согласовывается с администратором `@DitzmBack`: пользователь выбирает сумму, пишет администратору и после проверки получает зачисление. Владелец зачисляет деньги через админ-панель на сайте во вкладке **«Покупатели»** (ID покупателя и сумма, либо быстрые кнопки +500 / +1000). Через API это `POST /api/admin/balance` с телом `{"user_id": 123456789, "amount": 500}`.

## Уведомления о пополнении

Когда владелец загружает автовыдачу, бот сразу рассылает **всем, кто запускал бота** (кроме заблокировавших): фотографию категории, название товара, цену и остаток, плюс кнопку **«🛒 Купить»**, которая открывает карточку этого товара. Рассылка идёт фоновой задачей с ограничением одновременности; тем, кто заблокировал бота, сообщения больше не отправляются.

## Предзаказ, автовыдача и тестовые товары

- **Предзаказ по предоплате 100 %.** Владелец включает предзаказ на конкретном товаре в админ-меню. Если товара нет в наличии, кнопка в карточке становится «⏳ Предзаказ · предоплата 100 %» (в чате и в мини-лавке). Оформленный предзаказ виден покупателю в профиле → «⏳ Предзаказы»; повторное нажатие не создаёт дубль. Когда владелец загружает товар, бот **сначала выдаёт оплаченные предзаказы в порядке оформления** и отправляет товар в чат, и только остаток выставляется на полку.
- **Автовыдача.** В админ-меню есть «📤 Добавить автовыдачу»: бот просит список, где **одна строка = одна единица** (логин:пароль, ключ, ссылка; до 200 строк по 2000 символов). В карточке товара можно открыть «🧰 Изменить строки автовыдачи», заменить или удалить любую готовую строку. Отмена пополнения возвращает на полку товара.
- **Тестовые товары.** Флажок «🧪 Тестовый товар» в админке. Такие товары видят только владелец и тестеры (`TESTER_IDS`). Тестер жмёт «🧪 Тестовая покупка без оплаты» — заказ создаётся сразу выданным, деньги не списываются, в статистику профиля покупка не попадает, а бот мгновенно отправляет строку товара в чат.

## Отзывы

После выдачи товара бот спрашивает «Как тебе покупка?» и предлагает оценку 1–5 ⭐ или «Позже»; затем можно дописать текст отзыва сообщением либо нажать «Готово». Один отзыв на позицию заказа — повторная оценка обновляет прежнюю, а поставить её можно только по заказу со статусом `paid`/`done` и только за товар из этого заказа. Отзывы видны в карточке товара (средняя оценка и кнопка «📝 Отзывы»), в админ-меню («⭐ Отзывы») и в статистике.

## Админка в боте

Команды `/admin`, `/add`, `/id` и `/cancel` **скрыты из списка команд** (там только `/menu`), а посторонним бот на них не отвечает и не подсказывает про `ADMIN_IDS`.

`/admin` открывает меню в чате:

- **➕ Добавить товар** — выбор полки, типа (обычный/тестовый), затем название, цена, остаток, описание.
- **✏️ Редактировать товар** — список товаров → карточка управления: название, цена, остаток, описание, категория, предзаказ, тестовый, показ на полке.
- **📤 Пополнить товар** — список → строки автовыдачи (сначала предзаказы, остаток на полку).
- **🗑 Удалить товар** — подтверждение вторым нажатием.
- ** Заказы** — отметить оплату или выдать товар вручную.
- **📊 Статистика** и **⭐ Отзывы**.

## Админ-панель на сайте

Полноразмерная панель для обычного браузера (не мини-апп) — страница **`GET /admin`**, файл `webapp/admin.html`. Открывается с того же домена, что и бот: `https://<твой домен>/admin`. Экран под ширину 1180px, вкладки:

- **Товары** — список с остатками, правка названия, цены, остатка, описания, гарантии, категории, строк автовыдачи, тумблеры «Предзаказ», «Тестовый», «Показ на полке» и удаление с подтверждением.
- **Добавить товар** — создание позиции на выбранной полке.
- **Заказы** — отметка оплаты, выдача и отмена.
- **Покупатели** — список и пополнение баланса.
- **Отзывы** — последние оценки.

Вход по секрету `ADMIN_PANEL_TOKEN`: токен вводится один раз и запоминается в браузере, дальше уходит в заголовке `X-Admin-Token`. Он даёт те же права, что `ADMIN_IDS`, поэтому это длинный случайный секрет, а не пароль из словаря.

Правка товара из панели идёт методом `PATCH` и меняет только переданные поля — флаги «Предзаказ» и «Тестовый» при сохранении карточки не сбрасываются.

Мини-приложение с той же админкой продолжает работать на `WEBAPP_URL`; там отдельный пароль не нужен — сервер проверяет подпись Telegram `initData` и сравнивает ID с `ADMIN_IDS`.

## Установка и запуск

Нужен Python 3.10 или новее и **PostgreSQL** (подойдут Supabase, Neon и любой обычный сервер).

```sh
python -m venv .venv
# Активируй окружение: Windows — .venv\Scripts\activate; Linux/macOS — source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Перед запуском задай переменные окружения. Файл `.env` автоматически не читается.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Секретный токен от BotFather. Только в окружении хостинга, не в GitHub |
| `DATABASE_URL` | **Обязательно.** Строка подключения PostgreSQL: `postgresql://user:pass@host:5432/db` |
| `WEBAPP_URL` | Публичный HTTPS-адрес этого Python-приложения |
| `ADMIN_IDS` | Числовые Telegram ID владельцев, через запятую |
| `TESTER_IDS` | Telegram ID тестеров через запятую: им видны тестовые товары и доступна тест-покупка без оплаты |
| `ADMIN_PANEL_TOKEN` | Секрет для входа в админ-панель на сайте (`/admin`). Без него страница панели отдаётся, но вход и `/api/admin/*` по токену не работают |
| `SUPPORT_USERNAME` | Telegram username поддержки без `@`; по умолчанию `DitzmBack` |
| `BOT_USERNAME` | Username бота без `@` — из него собирается реферальная ссылка |
| `DB_SSL` | `disable` или `require`. По умолчанию `require` для внешней базы и без SSL для `localhost` |
| `DB_POOL_MIN` / `DB_POOL_MAX` | Размер пула соединений; по умолчанию 1 и 10 |
| `DB_STATEMENT_CACHE` | `1` включает кэш подготовленных запросов (по умолчанию выключен — для pgbouncer/Supabase-пулера) |
| `DB_SCHEMA` | Схема Postgres; по умолчанию `public` |
| `HOST` | По умолчанию `0.0.0.0`, чтобы контейнерный хостинг мог принять внешний трафик |
| `PORT` | Порт хостинга; по умолчанию `8080` |
| `WEB_ONLY` | `1` для локального просмотра каталога без запуска бота; не для рабочего бота |

## Проверка

```sh
python -m unittest discover -p "test_*.py" -v
```

Тесты работают против настоящего Postgres и **пропускаются**, если не задан `TEST_DATABASE_URL` (или `DATABASE_URL`). Каждый тест создаёт свою схему `test_w0`, `test_w1`, … и удаляет её после себя, поэтому рабочие таблицы не затрагиваются. Против обычной базы:

```sh
TEST_DATABASE_URL="postgresql://user:pass@host:5432/db" python -m unittest discover -p "test_*.py" -v
```

`GET /health` возвращает `{"ok": true}`. Публичные API: `/api/catalog`, `/api/products`, `/api/config`. `/api/me`, создание заказа и `/api/admin/*` требуют подписанного Telegram `initData` в заголовке `Authorization: tma ...` либо, для админ-панели, заголовка `X-Admin-Token` с секретом `ADMIN_PANEL_TOKEN`. Заказы защищены от дублирования при повторе запроса.

## Перенос данных и хостинг

SQLite больше не поддерживается: код, `aiosqlite`, `DB_PATH` и PRAGMA удалены. Схема создаётся при старте (`CREATE TABLE IF NOT EXISTS` + `ALTER TABLE … ADD COLUMN IF NOT EXISTS`), старые товары, заказы и категории в PostgreSQL сохраняются, а прежние демо-категории скрываются из публичного каталога без удаления записей.

Публикация исходников в GitHub **не запускает бота**. На хостинге выбери репозиторий, команду установки `python -m pip install -r requirements.txt`, команду запуска `python app.py`, задай окружение (в первую очередь `DATABASE_URL`) и перезапусти сервис. После получения домена запиши его в `WEBAPP_URL`. Запускай только один polling-процесс на один токен; если ранее был настроен webhook, сначала отключи его.
